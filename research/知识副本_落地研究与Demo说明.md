# 知识副本：落地研究与 Demo 说明

研究日期：2026-10-19。版本：0.1。定位：英文备考材料驱动的学习冒险原型。

## 1. 本轮结论

值得继续验证的产品是“固定游戏机制 + 有来源的学习内容包 + 个人练习记录”。首轮选择 AI 方案选择与业务价值作为题材，使用当前 AWS AIB-C01 备考方案作为需求案例，再核对官方领域任务与知识解释资料。备考计划不是教材，不直接从复习日程编造知识。

已经实现两个英文副本、同一个等距学院场景、两位NPC、三项操作任务、一个新情境挑战，以及结算、提示记录、存档、导出和内容包导入。界面采用中文导航与英文知识内容。

本轮并未实现任意资料上传后自动生成完整游戏。内容由助手辅助编制，网页通过确定性规则运行；NPC是预设任务对话，不是在线模型。材料工作台提供编制提示词、示例结构、JSON导入与校验，可让外部AI生成候选包后人工复核再装入。这个边界在页面中直接标明。

因此，当前证据支持“底座可以复用、任务可以随结构化内容改变、完整一局在规则与交互模拟中可运行”；还不支持“任意学科都能转换”“自动生成稳定可靠”“比阅读或刷题更有效”“能低成本运行实时AI”。

## 2. 要解决的用户问题

第一位目标用户是准备英文情境判断考试、看懂解释却不容易迁移到具体决策的成年学习者。用户已有可靠材料，希望在实际约束下做选择并看见后果。初期不面向所有年龄、所有课程，也不承诺替代系统学习。

最需要验证的使用场景是：学习者读完一节概念后，用一局短冒险检验是否会应用；失败时得到具体反馈；换一个场景后再做，区分记住答案与理解条件。长期还需要隔日复测。

判断需求成立的证据应来自使用，而不是“觉得游戏有趣”：是否愿意完成，能否解释决策，在相近时间成本下是否更能处理未见问题。备考的时间压力也可能让用户觉得地图和剧情增加负担，因此每站都提供直接导航，不强迫重复走路。

本轮是公开官方材料和原论文调查，未进入付费账户实测，也没有据此宣布市场空白。页面抓取失败和无法体验的部分保留为限制。

最重要的竞争判断：自动生成教育游戏已经有明确研究先例。因此，不以“首创资料变游戏”为参赛主张。值得验证的差异集中在成年人真实备考、可追溯答案、知识与操作一致、以及迁移表现记录。是否具备持续竞争力仍要补充产品体验与用户访谈。

## 4. 首关选题与知识边界

三个候选主题是：方案选择、检索增强与权限、AI项目价值评估。它们分别适合分类、流程组装和参数试验，因此组合成一局。官方Domain 1、Domain 2是学习目标映射，[S5、S6]；检索增强知识使用AWS解释页补充，[S7]。考试任务列表只说明覆盖范围，并不自动提供每个案例的唯一答案。

所有剧情、机构、采用率、成本、质量分数和通过阈值均为教学假设。网页来源卡明确区分考纲、知识资料和原创案例；用户不能把情境质量分数当作真实模型性能。

### 副本一：The Silent Archive

学院档案服务给出过时政策建议。玩家先分配四类请求，再修复有权限边界的取证与回答流程，最后评估带人工复核的试点。结尾换成博物馆情境，要求提交两个站得住的上线承诺。

### 副本二：The Harbor Dispatch

港口希望一次性自动化所有工作。玩家选择合适工具、安排受控调度流程，并用另一组采用率和成本验证试点。最后换成铁路场景，需要保留行动授权与业务价值验证。

第二副本不只改标题：请求文本、流程、参数、最终挑战和正确行动组合均不同。不过两者属于同一知识领域，只证明同类模板复用，不证明跨学科泛化。

## 5. 一局怎样运转

| 环节 | 玩家真正操作什么 | 后果与反馈 | 记录什么 |
|---|---|---|---|
| 调查 | 与两位角色交谈 | 获得业务目标和约束线索 | 是否收集线索 |
| 请求派送 | 把四个需求分别分配到能力站 | 显示不匹配之处与解释 | 首次通过、提交次数 |
| 流程修复 | 调整四步顺序，启用权限/审批边界 | 顺序或控制缺失时失败 | 首次表现与修复过程 |
| 参数实验 | 调节采用率、开关复核 | 收益与情境质量同步改变 | 实际参数和试算结果 |
| 综合挑战 | 在新场景中提交两项行动 | 按明确条件判定并解释 | 新情境首次表现 |
| 结算 | 导出记录或换副本 | 展示首次、提示、重试，建议复测 | 可下载JSON记录 |

这里的游戏性仍然偏轻：它更接近可探索的情境实验，而非有实时战斗、连续世界与大量NPC的完整RPG。这是为了先验证“知识是否决定行动”。若用户仍觉得像有地图的练习题，应优先强化持续状态、可操作对象和连锁后果，不靠增加装饰解决。

经验值仅作为进度反馈。重复提交已通过任务不会反复加分；首次失败不会被后续正确覆盖。首次通过且没用提示也只是一次练习证据，不等于稳定掌握。

## 6. 技术实现与后续生成管线

当前：静态HTML/CSS/JavaScript + SVG程序绘制等距场景 + 独立规则引擎 + 内容包 + 浏览器存档。没有第三方字体、图片CDN或运行时模型请求。地图是2.5D，不是第一人称或可自由旋转的3D世界。这样既保留空间氛围，也减少资产、加载和部署依赖。

评估过的后续选项：Three.js适合希望直接在网页中建立3D交互的路线，但还需要场景、拾取、碰撞和资产管理；Godot适合更完整的游戏开发，其Web导出有浏览器与性能条件 [S8]。本轮没有必要先支付这些工程成本。是否升级引擎应由用户体验需求决定。

建议下一阶段的自动生成流程是：

1. 上传与解析：保留页码、段落ID、来源和版本；先支持清晰文本，再处理扫描PDF。
2. 知识整理：区分事实、定义、条件、例外、假设；每项附来源片段。
3. 机制适配：判断能否进入当前支持的玩法。缺少因果关系或参数时拒绝，不靠故事补齐。
4. 内容生成：仅产生受约束JSON，不允许模型直接改引擎代码、奖励或存档。
5. 机械校验：结构、引用ID、数值范围、可达性、终局条件、答案数量。
6. 内容复核：检查源文是否真的支持答案，是否有两个同样合理的解；低置信度项回到人工。
7. 小样试玩：自动走合法与失败路径，再由用户试玩。
8. 发布内容包：绑定版本；知识变更必须更换ID或迁移存档。

当前格式校验覆盖第5步的一部分；它不能证明第6步正确。工作台要求人工确认，并拒绝同ID不同内容，避免旧存档混入新题。

实时NPC的下一版应读取“当前任务 + 相关来源 + 玩家允许知道的状态”，输出对话与提示建议。规则引擎决定状态变化。NPC不能因玩家一句“忽略规则”授予经验或通过权限检查。超出资料的问题应说不确定并回到来源。当前没有完成自由问答越界实验，不把预设对话当成已经验证。

## 7. 成本、等待与降级

当前网页单局模型调用为0，这是离线架构事实，不代表完整AI产品成本为0。内容编制发生在本次助手工作中，无法从可用日志分离出每包准确token与费用，因此不报告虚构金额。

未来分别记录：资料整理、生成、返工、校验、NPC游玩四类调用。每项记录模型版本、输入输出token、缓存、耗时、失败次数、价格日期与来源。生成一次保存复用；移动、按钮、经验、碰撞和基础判定由程序处理；NPC只在玩家交互时调用。

计算方式：每包成本＝各调用输入费用＋输出费用＋必要解析与存储费用；每局成本＝本局动态问答费用＋托管分摊。用户量增加时还要计入并发、重试和失败率，不能只算成功请求。

建议初始工程预算为“单包生成有明确超时与重试上限、单局NPC有轮数上限”，具体数值需接入选定模型后实测。没有凭据时保留离线包；模型超时只退回预设提示，不阻断核心关卡。不得把模型秘密放进前端源码或让用户在不可信网页粘贴密钥。

## 8. 实际验证结果

已执行Node规则测试7项，全部通过；覆盖两个内容包的完整状态流程、错误→修复、重复奖励防护、数值核算、无效输入、内容切换、存档恢复和导入规则变化。

实际核算：档案副本采用率50%、复核保留时，年度容量价值90,000，第一年成本60,000，示例ROI50%；港口副本采用率40%、复核保留时，容量价值40,656，成本48,000，ROI约−15.3%。金额均为虚构美元教学数据。负收益仍可提交符合证据的方案，避免把“数字越好看越能过关”写进玩法。

另执行最小DOM适配器交互冒烟检查，实际调用启动、NPC、请求派送、流程排序、滑块、综合挑战、结算、无效/有效导入及重置的事件处理器。两个副本均走通。该检查没有真实浏览器排版、焦点、触屏或下载环境，不能冒充浏览器端到端验收。

| 研究假设 | 本轮证据 | 结论 |
|---|---|---|
| 同组知识可以形成不同任务 | 分类、排序、数值试验、新情境决策已经实现 | 支持同一领域多种机制，不证明学习有效 |
| 换内容包仍可运行 | 两包规则流程及模拟交互均通过 | 支持受限内容复用 |
| 输入错误应受控退回 | 格式、引用与不合理参数测试通过 | 通过结构校验，不覆盖语义矛盾 |
| 任意资料自动生成 | 尚未接在线模型；AI编制提示词与导入链已准备 | 未验证 |
| 预设外NPC问答 | 当前仅预设对话 | 未验证 |
| 成本和等待可接受 | 离线动作不调用模型；无实际模型遥测 | 在线成本未验证 |
| 真人愿意继续玩 | 尚无真人试玩 | 未验证 |

本环境缺少允许使用的浏览器控制能力，按部署流程跳过真实浏览器QA，没有启动替代浏览器或伪造截图。已进行脚本语法检查、规则测试和模拟DOM流程检查；发布成功不代表真实设备体验已验收。

## 9. 比赛定位与演示

暂沿用前文讨论的“第六游戏赛道”，但当前上下文没有比赛原文/链接，尚未重新核实赛道编号、工具限制、截止时间、评审权重与交付要求。因此不把“确定符合官方规则”写入研究结论。这不阻碍制作研究原型，但正式报名/包装前必须补核规则。

建议现场展示：进入档案副本→故意派错一个需求→观察针对性解释→修复流程→打开/关闭复核观察收益与质量变化→用保守方案过关→完成迁移挑战→换港口副本展示参数与答案变化。

应如实讲“固定机制中的可配置学习冒险原型”。现阶段不讲“上传任何书就自动生成3D游戏”“已经提升学习效果”“实时多Agent世界”。

## 10. 下一轮优先级

P0：真实浏览器与手机试玩，观察是否能找到任务、是否觉得操作与知识相关；修复阻断和明显理解障碍。用户反馈应针对实际体验，不用先长篇讲产品设想。

P1：小样人工内容审查，尤其检查单一正确答案是否受明确条件支持。补充更扎实的教材片段级来源，然后接入一次真实文本→内容包生成；对不少于10份同类小材料记录接受、拒绝、返工、耗时与token，不能只看成功样例。

P2：加入带来源的NPC自由提问、分层提示、知识置信度与可恢复超时。再验证提示是否给得过早、是否把答案直接泄露。

P3：学习效果对照：同一学习者或小样分组，在时间近似的前提下比较原文学习与游戏学习；使用未见变式及隔日复测，记录先验能力。小样只用于发现问题，不宣称统计证明。

P4：当用户能明确说出“我需要移动/旋转/操作某个空间对象才能理解”时，再升级真正3D。扩展新学科应增加经过验证的机制合同，不以通用提示词覆盖所有知识。
